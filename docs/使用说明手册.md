# FRU 自动化工具 — 使用说明手册

**产品：** FRU 自动化整合工具（FruTool）  
**适用版本：** 5.5.0  
**适用对象：** 现场硬件运维（BMC / FRU / 换板 / PCIe 拓扑）

---

## 1. 开始之前

### 1.1 运行环境

- Windows 10 / 11
- 首次启动会请求 **管理员权限**（UAC），用于本机网卡与 DHCP 等操作
- 需要能访问目标服务器 BMC 网络（通常为本机网线直连或同网段）

### 1.2 如何启动

**打包版（推荐现场使用）**

1. 解压或拷贝整个 `FRUTool` 文件夹到本机（不要只拷单个 exe）
2. 双击 `FRUTool.exe`
3. 同意 UAC 提权

**开发版**

```powershell
python fru_tool.py
```

### 1.3 目录与可覆盖资源

以 `FRUTool.exe` 所在目录为根：

| 路径 | 说明 |
|------|------|
| `FRUTool.exe` | 主程序 |
| `_internal/` | 打包内置资源（勿随意删） |
| `ipmitool/` | **可覆盖**：放在 exe 同目录即可替换内置 ipmitool / 拓扑脚本 |
| `PCLE/` | **可覆盖**：PCIe 拓扑压缩包库 |
| `fru_backup/` | 运行后生成：FRU 备份、换板会话 |
| `logs/` | 运行后生成：按日日志、拓扑索引与脚本偏好 |

更换 ipmitool 或拓扑脚本时，把新文件放到 **exe 同目录的 `ipmitool/`**，无需重新打包。

## 2. 界面总览

左侧活动栏（自上而下）：

| 入口 | 用途 |
|------|------|
| **换板流程** | 自动 / 手动换板 |
| **FRU 字段刷写** | 读、改、批量写 FRU |
| **PCIe 拓扑刷写** | 选脚本与 .bin，写入 EEPROM |
| **连接与网络** | 旧/新板账号密码、本机网卡 |

底部：**终端日志**（可按全部 / DHCP / FRU / 拓扑过滤）、本机与 BMC 状态、版本号。

主题：底栏可切换「跟随系统 / 深色 / 浅色」。

## 3. 连接与网络（必做）

刷写 FRU、换板、拓扑前，先在此页配好网络与账号。

1. 填写 **旧板账号 / 旧板密码**、**新板账号 / 新板密码**（可勾选显示密码）
2. 在 **本机 IPv4** 下拉中选择连接 BMC 的网卡，必要时点 **刷新网卡**
3. 摘要中会显示 BMC 将分配的地址等信息
4. 选择可用静态网卡后，工具会按需启动内置 DHCP（无需单独开关）
5. 等待底栏显示 BMC 在线后再做后续操作

**说明**

- 拓扑刷写、多数 FRU/换板写操作使用 **新板** 账号密码
- 若网卡处于 Windows DHCP 客户端模式，内置 DHCP 可能不会启动，请按现场网络规范配置静态 IP

---

## 4. FRU 字段刷写

1. 确认 BMC 在线
2. 进入 **FRU 字段刷写**
3. 点 **尝试读取 FRU**（或按界面提示读取）
4. 在 Chassis / Board / Product 各组中编辑需要的字段
5. 确认后点 **刷写所有非空字段**
6. 需要放弃未提交修改时用 **重置**

操作过程可在底部终端的 **FRU** 标签中查看日志。

---

## 5. 换板流程

进入 **换板流程**。顶部可切换 **手动 / 自动**，必要时 **重置进度**。

### 5.1 手动换板

典型顺序：

1. 填写 **旧服务器 SN**
2. 点 **导出 FRU 备份**（步骤 1）
3. 物理换板并确认新板 BMC 上线
4. 点 **克隆 FRU 并还原 SN**（步骤 2；Board Serial 会按流程还原）
5. 如需恢复新板出厂 FRU，使用 **回滚新板原始 FRU**

**备份文件名**

| 类型 | 命名示例 | 说明 |
|------|----------|------|
| 工具导出 | `SN123_20260820_2047.bin` | `{SN}_时间戳.bin` |
| 手导 / 投放 | `SN123.bin` | 仅 `{SN}.bin`，工具同样识别 |
| 新板原始备份 | `SN123_NEW_ORIGINAL_时间戳.bin` | 克隆前另存，供回滚 |

若 `fru_backup/` 中已有该 SN 的匹配备份，填写 SN 后可 **跳过步骤 1**，直接做步骤 2。

### 5.2 自动换板

1. 切换到 **自动**
2. BMC 上线后自动读 FRU，弹窗核对 SN
3. 确认后自动导出 → 等待旧板离线 → 等待新板上线 → 自动克隆
4. 弹窗中可 **确认并导出** 或 **取消自动流程**（Product Serial 为空时无法自动继续）

过程中勿强行结束程序；界面会提示硬件写入中关闭有风险。

## 6. PCIe 拓扑刷写

进入 **PCIe 拓扑刷写**。

### 6.1 选择拓扑脚本

1. 在 **拓扑脚本** 下拉中选择 `PcieEEpromTool*.py` 版本
2. 点 **刷新** 可重新扫描
3. 扫描范围：exe 旁、`ipmitool/`、打包内置
4. 上次选择会记住（`logs/topo_prefs.json`）

**重要：** 脚本必须在 `ipmitool/` 目录下才能真正执行。若选中的是其它位置的文件，工具会在刷写前将其 **加载** 为：

`ipmitool/PcieEEpromTool_run.py`

再运行（不覆盖原来的 `PcieEEpromTool.py`）。

多版本脚本建议直接放在 exe 同目录的 `ipmitool/` 下，例如：

- `ipmitool/PcieEEpromTool.py`
- `ipmitool/PcieEEpromTool_v2.py`

### 6.2 选择拓扑 .bin

任选其一：

- **浏览** 本地 `.bin`（通常 ≤ 512 字节）
- 在 **匹配套餐拓扑** 中点选推荐卡片（按新板 FRU 套餐号预加载）
- 在 **PCLE 拓扑库** 中筛选厂商 / 机型 / 套餐 / 压缩包名后点选

### 6.3 开始刷写

1. 确认 BMC 在线，且已选脚本与 `.bin`
2. 点 **开始刷写拓扑文件**
3. 使用连接页中的 **新板账号密码** 与当前 BMC IP 写入 EEPROM（偏移 0x7E00）
4. 结果见终端 **拓扑** 标签

PCLE 压缩包库放在 exe 旁 `PCLE/` 即可覆盖内置库。

- 底部 **展开终端** 查看实时输出

- 拓扑脚本偏好：`logs/topo_prefs.json`

## 8. 常见问题

| 现象 | 处理建议 |
|------|----------|
| BMC 一直离线 | 检查网线、本机网卡选择、账号密码、是否已提权管理员 |
| 拓扑刷写失败 | 确认脚本在 `ipmitool/` 或允许被加载；确认 `.bin` ≤ 512 字节；看拓扑日志 |
| 找不到拓扑脚本 | 把 `PcieEEpromTool*.py` 放到 exe 同目录 `ipmitool/`，点 **刷新** |
| 换板找不到备份 | 确认 SN 与 `fru_backup/` 中 `{SN}.bin` 或 `{SN}_时间戳.bin` 一致 |
| 打包版提示缺 Python | 拓扑脚本需本机可运行的 Python（`python` / `py -3`）；装好后重开工具以便继承 PATH |
| 误关程序 | 刷写 FRU / 拓扑过程中不要强制结束，以免 EEPROM 异常 |

---

## 9. 安全与注意

- 仅在授权机房 / 授权设备上使用
- 账号密码会出现在内存与部分日志脱敏流程中，勿把 `logs/`、`fru_backup/` 随意外传
- 换板与拓扑写入会改动硬件非易失数据，操作前确认 SN、机型与拓扑版本
