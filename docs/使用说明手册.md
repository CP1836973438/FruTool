# FRU 自动化工具 — 使用说明手册

**产品：** FRU 自动化整合工具（FruTool）  
**适用版本：** 6.0.2   
**适用对象：** 现场硬件运维（BMC / FRU / 换板 / PCIe 拓扑）

**Markdown 使用手册（含截图）：** [使用手册.md](使用手册.md)


---

## 1. 产品定位

FruTool 是 **多功能** 现场工具，不是单一流水线。四个模块可按任务独立使用：

| 模块 | 作用 | 与其它模块关系 |
|------|------|----------------|
| **连接与网络** | 网卡、DHCP、旧/新板凭据、BMC 在线状态 | **唯一公共前提**：凡访问 BMC 必先配好 |
| **换板流程** | 旧板 FRU 备份 → 换板 → 克隆并还原新板 SN（PN 不同时一并还原） | 与 FRU/拓扑无强制先后 |
| **FRU 字段刷写** | 读取当前板 FRU 并在字段框展示，再按字段改写 | 与换板不同：非整包身份迁移 |
| **PCIe 拓扑刷写** | 拓扑 `.bin` → EEPROM 0x7E00 | 可单独做，也可换板后再做 |

```text
          ┌─→ 换板流程
连接就绪 ─┼─→ FRU 字段刷写
          └─→ PCIe 拓扑刷写
```

## 2. 开始之前

### 2.1 运行环境

- Windows 10 / 11
- 首次启动会请求 **管理员权限**（UAC），用于本机网卡与 DHCP 等操作
- 需要能访问目标服务器 BMC 网络（通常为本机网线直连或同网段）

### 2.2 如何启动

**打包版（推荐现场使用）**

1. 解压或拷贝整个 `FRUTool` 文件夹到本机（不要只拷单个 exe）
2. 双击 `FRUTool.exe`
3. 同意 UAC 提权

**开发版**

```powershell
python fru_tool.py
```

### 2.3 目录与可覆盖资源

以 `FRUTool.exe` 所在目录为根：

| 路径 | 说明 |
|------|------|
| `FRUTool.exe` | 主程序 |
| `_internal/` | 打包内置资源（勿随意删） |
| `ipmitool/` | **可覆盖**：ipmitool / 拓扑脚本 |
| `PCLE/` | 用户投放拓扑库：启动时自动建，并按厂商建子目录。程序再同步到 `_internal/PCLE/` 供加载（详见 [8.3](#83-拓扑-bin-放哪)） |
| `fru_backup/` | 运行后生成：FRU 备份、换板会话 |
| `logs/` | 运行后生成：按日日志、拓扑索引与脚本偏好 |

更换 ipmitool、拓扑脚本时放到 **exe 同目录的 `ipmitool/`**；自己的拓扑 `.bin` 放到 **exe 同目录 `PCLE/<厂商>/`**，都不必重新打包。

## 3. 界面总览

左侧活动栏（自上而下）：换板流程 → FRU 字段刷写 → PCIe 拓扑刷写 → 连接与网络。

底部两层：

- **日志条**（内容区最底下）：最新一条日志 + **展开终端**；点这一条也能打开右侧终端。详见 [10](#10-终端与日志)
- **状态栏**（窗口最底下）：本机 / BMC；BMC 在线后地址变蓝可点。版本号、主题（跟随系统 / 深色 / 浅色）

BMC 在线后，底栏地址会变成**蓝色可点文字**（不是连接页中间那块状态卡片）。点击后打开 BMC 网页，并尝试把当前板对应密码复制到剪贴板，详见 [4.4](#44-底栏-bmc-地址变蓝后)。

## 4. 第一步（唯一公共）：连接与网络

凡 FRU 刷写、换板、拓扑，只要访问 BMC，都先完成本页。配好后可随意切换其它模块，无需按固定顺序「走完所有功能」。

### 4.1 本页内容

| 区域 | 说明 |
|------|------|
| 连接状态 | 本机、BMC 是否就绪（此处 IP **不可点**） |
| 旧板凭据 | 旧主板账号/密码（换板读旧板常用；点底栏蓝色地址时也会用来试登） |
| 新板凭据 | 新主板账号/密码（**拓扑与多数写操作默认用这一组**） |
| 显示密码 | 核对密码 |
| 本机 IPv4 / 刷新网卡 | 选择连 BMC 的网卡 |
| 摘要 | 本机地址、将分配给 BMC 的地址、掩码 |
| **底栏 BMC 地址** | 在线变蓝后可点：开网页 + 复制密码（见 [4.4](#44-底栏-bmc-地址变蓝后)） |

### 4.2 操作步骤

1. 接好网线（直连 BMC 或同网段）。
2. 填写旧板、新板账号密码。
3. 选择本机网卡，必要时 **刷新网卡**。
4. 工具按网卡情况自动处理内置 DHCP（一般无单独开关；与网上深度远程启动管理器的差别见 [4.5](#45-内置-dhcp对照网上深度远程启动管理器)）。
5. 等待「本机与 BMC 均已就绪」。底栏「BMC」后面的地址变成**蓝色**后，可点开网页并复制密码（见下节）。
6. 到此第一步结束，再去做换板 / FRU / 拓扑。

### 4.3 注意

- 网卡若为 Windows DHCP 客户端（「自动获取 IP」），内置 DHCP 会暂停，避免干扰办公网；产测请改静态后再刷新网卡。
- 拓扑页使用 **新板账号密码 + 当前 BMC IP**。
- **不要**与网上深度远程启动管理器、VMware/Hyper-V 自带 DHCP、Windows 连接共享等同时抢 UDP 67。

### 4.4 底栏 BMC 地址变蓝后

连接页中间的状态卡片只显示是否就绪。真正可点的是窗口**最底下状态栏**里的 `BMC x.x.x.x`：

1. BMC 探测成功后，该地址从灰色变成**蓝色**，鼠标变成手型。
2. **单击一次**会同时做两件事：
   - 用系统默认浏览器打开 `http://<BMC地址>`（BMC Web 管理页）。
   - 后台用 IPMI 先试旧板账号、再试新板账号，哪一组能读到 Board Serial，就把**那一组密码**写入系统剪贴板。
3. 终端会出现「已自动复制旧板/新板密码到剪贴板」，到浏览器登录页直接粘贴即可。
4. 若两组都试不通，网页仍会打开，但日志提示未复制密码——先核对连接页里填的账号密码。

离线时底栏显示 `BMC —`，不可点。

### 4.5 内置 DHCP（对照网上深度远程启动管理器）

**为什么要自带 DHCP：** 当初做这个程序，就是因为现场用网上深度远程启动管理器（下称「网深」）给 BMC 分地址时，**有时会卡住、根本不分配**。网深是给 PC 做 PXE/无盘的大工具，环节多，BMC 只要一个地址，卡在网深里很难判断卡在哪一步。FruTool 内置 DHCP 只服务当前这块 BMC 网口，握手过程写在终端 **DHCP** 标签（Discover → Offer → ACK），分没分到一眼能看出来。

它**不是网深的替代品**（不能拿来装系统/无盘），也**不要和网深同时开**。

| 对比项 | 网上深度远程启动管理器 | FruTool 内置 DHCP |
|------|------------------------|-------------------|
| 要解决的问题 | PC 远程启动、无盘、批量装机 | 网深偶发卡住、BMC 要不到地址 → 专给 BMC 发一个地址 |
| 给谁用 | 给 **PC** | 只给 **BMC** 一块网口，方便笔记本直连做 IPMI |
| 带什么服务 | DHCP + TFTP + PXE 启动菜单，服务多台机器 | **只有** DHCP 四步握手，无 PXE、无启动文件 |
| 地址怎么发 | 自己配作用域、地址池、MAC 绑定 | 按当前所选**静态网卡**的网段固定发 **一个** 地址（优先主机号 `.100`，本机已占用则改 `.101` 等） |
| 卡住时怎么看 | 界面不一定立刻说明卡在 Discover 还是 Offer | 打开终端 **DHCP** 标签：有 Discover / Offer / ACK 就知道走到哪 |
| 怎么开关 | 单独开软件、手工配作用域 | 选对静态网卡后**自动**启停，连接页没有 DHCP 开关 |
| 办公网 | 全网广播，容易和现有 DHCP 抢答 | 网卡若是 Windows「自动获取 IP」，**自动暂停**，避免搅办公局域网 |
| 换板拔线 | 视网深配置而定 | 拔线期间仍监听，避免新板错过 Discover |
| 同时开？ | 会占 **UDP 67** | 占不到 67 则本工具 DHCP 起不来；**先关网深**（以及 VMware/Hyper-V DHCP、ICS）再刷新网卡 |

连接页摘要行会写清「本机 IPv4」和「分配给 BMC」的地址。分配成功后看终端 **DHCP** 标签；随后底栏 BMC 应变蓝。

## 6. 换板流程

### 6.1 功能说明

将旧板 FRU 身份备份并写入新板。克隆后始终还原新板 Board Serial；若新旧主板 Board Part Number 不一致，再写回新板 PN。支持手动 / 自动、跳过已有备份的步骤 1、克隆前新板原始备份与回滚。

顶部可切换 **手动 / 自动**，必要时 **重置进度**。

### 6.2 备份命名（`fru_backup/`）

| 类型 | 命名示例 | 说明 |
|------|----------|------|
| 工具导出 | `SN123_20260820_2047.bin` | `{SN}_时间戳.bin` |
| 手导 / 投放 | `SN123.bin` | `{SN}.bin`，同样识别 |
| 新板原始 | `SN123_NEW_ORIGINAL_时间戳.bin` | 克隆前另存，供回滚 |

填入 SN 后若已有匹配备份 → **可跳过步骤 1**，直接步骤 2。

### 6.3 手动流程

1. BMC 在线，模式选手动。
2. 填 **旧服务器 SN** → **导出 FRU 备份**（连旧板时执行）。
3. 物理换板，确认新板 BMC 在线（密码/网卡无误）。
4. **克隆 FRU 并还原 SN**（PN 不同时会一并还原新板 Board Part Number）。
5. 异常时用 **回滚新板原始 FRU**。

### 6.4 自动流程

1. 切换自动。
2. BMC 上线 → 读 FRU → 弹窗核对 SN。
3. **确认并导出** 或 **取消**（Product Serial 为空不能自动继续）。
4. 等旧板离线 → 新板上线 → 自动克隆。
5. 写入中勿强制结束程序。

## 7. FRU 字段刷写

### 7.1 功能说明

对 **当前在线 BMC** 做字段级读写（Chassis / Board / Product），不是整包换板。

BMC 在线后，本页会自动读取当前板 FRU，并在 Chassis / Board / Product 各**字段框里用灰字展示现有值**。灰字仅供核对，不会被当成写入内容。要改哪个字段，在对应框里输入新值；没输入的字段不会被覆盖。空字段不会被刷写。

### 7.2 操作步骤

1. 连接就绪（BMC 在线）。
2. 进入 FRU 页，等字段框出现当前 FRU 值（灰字）。若没有，稍等或点 **尝试读取 FRU**。
3. 在需要改的框里输入新值。
4. **刷写所有非空字段**；日志看 **FRU** 标签。
5. 放弃编辑用 **重置**。

**与换板区别：** 换板 = 旧板整包身份迁到新板；本页 = 当前板字段微调。

## 8. PCIe 拓扑刷写

### 8.1 功能说明

将拓扑 `.bin` 写入 EEPROM（0x7E00）。含：刷写区、按 FRU 套餐号的 **匹配套餐拓扑**、可筛选的 **PCLE 拓扑库**；支持多版本脚本下拉与记忆。

### 8.2 选择拓扑脚本

1. **拓扑脚本** 下拉选择 `PcieEEpromTool*.py`；**刷新** 重新扫描。
2. 扫描范围：exe 旁、`ipmitool/`、打包内置；偏好写入 `logs/topo_prefs.json`。
3. **执行约束：** 脚本须在 `ipmitool/` 下运行。其它位置选中时，刷写前加载为 `ipmitool/PcieEEpromTool_run.py`（不覆盖主脚本）。
4. 现场建议多版本直接放在 exe 旁 `ipmitool/`。

### 8.3 拓扑 .bin 放哪

现场自己补拓扑文件，分两种用法：

| 用法 | 放哪 | 何时用 |
|------|------|--------|
| **进库、以后还能按套餐匹配** | **`FRUTool.exe` 同目录 `PCLE/<厂商>/`** | 长期维护、多机型、要出现在「PCLE 拓扑库 / 匹配套餐」 |
| **只刷这一次** | 任意位置（U 盘、桌面均可） | 点刷写区 **浏览** 选文件即可，不必拷进程序目录 |

**进库时怎么放：**

1. 启动程序后，exe 旁边会自动出现 `PCLE/`，里面已有厂商文件夹（与 Infill 白名单一致：FOXCONN、H3C、Maginfra、Inspur、Lenovo、Changkuai、Nettrix、Inventec、HuaQin、Kunlun、LITAO）。
2. 把厂商给的 `.bin` 或 zip/7z/rar 放进对应厂商文件夹，例如 `PCLE/Inspur/S62D1-I8DD2M-L.bin`。子目录也会扫到。
3. **文件名（不含 `.bin`）必须等于套餐号**，与 FRU Product Extra 里 `Suite:` 后面那串一致。
4. 单个 `.bin` **不超过 512 字节**。
5. 程序会把这些文件同步到 **`_internal/PCLE/`** 再加载进拓扑库。不要手改 `_internal/PCLE/`（升级会清）。不要放进 `fru_backup/` 或 `ipmitool/`。
6. 放好后切到拓扑页点 **刷新**（或重新打开工具），库和「匹配套餐」才会更新。

打包版不再内置出厂压缩包；现场库完全来自你放进 `PCLE/<厂商>/` 的文件。

### 8.4 选择要刷的文件

任选其一：

- **浏览** 任意本地 `.bin`
- **匹配套餐拓扑** 卡片（可含「推荐」）——依赖 `PCLE/<厂商>/` 里按套餐号命名的文件
- **PCLE 拓扑库** 按厂商 / 机型 / 套餐 / 包名或裸 bin 名筛选后点选

### 8.5 开始刷写

1. BMC 在线，脚本与 `.bin` 已选。
2. **开始刷写拓扑文件**（新板账号密码 + 当前 BMC IP）。
3. 结果见终端 **拓扑** 标签。

PCLE 库维护见 [8.3](#83-拓扑-bin-放哪)。打包版需本机 Python（`python` / `py -3`）可用。

## 10. 终端与日志

窗口内容区最底下有一条**日志条**：最新一条日志（颜色表示信息 / 成功 / 警告 / 错误）和 **展开终端** 按钮。点这条或点按钮，会在窗口**右侧**打开终端面板（可拖左边细条改宽度）。再往下的状态栏是本机/BMC 地址，不是日志条。

### 10.1 日志面板

| 操作 | 说明 |
|------|------|
| **全部 / DHCP / FRU / 拓扑** | 四个标签。DHCP 看分地址，FRU/换板看刷写，拓扑看 EEPROM；一条日志会进「全部」，并按内容进对应标签 |
| 未读数字 | 面板收起或没看这个标签时，新日志会在标签上出数字 |
| **清空** | 只清**当前标签**，其它标签还在 |
| **收起** | 关右侧面板，底栏变回那条日志条 |
| 自动滚到底 | 新日志到来时跟到最新一行 |

现场排障建议：DHCP 卡住先切 **DHCP**；换板/字段刷写切 **FRU**；拓扑刷写切 **拓扑**。

### 10.2 命令行（面板底部）

| 控件 | 说明 |
|------|------|
| **IPMI / 自由** | IPMI：只发 ipmitool 子命令（如 `fru list 0`），自动带上当前 BMC 地址和账号密码。自由：本机 Shell 命令 |
| **新 / 旧** | 仅 IPMI 模式：用连接页里的新板或旧板凭据 |
| 回车 | 执行当前命令 |
| Tab | 补全 |
| ↑ / ↓ | 历史命令 |
| Ctrl+C | 自由模式下打断正在跑的命令 |

IPMI 命令结果会出现在 **FRU**（及全部）标签。不要在刷写进行中乱发会改 EEPROM/FRU 的命令。

### 10.3 落盘文件

相对 exe 目录：`logs/YYYYMMDD.log`（按日全文）、`topo_index.json`、`topo_prefs.json`。界面清空不影响磁盘日志。

## 11. 常见问题

| 现象 | 处理建议 |
|------|----------|
| BMC 一直离线 | 网线、网卡、账号密码、管理员权限；若开着网深/其它 DHCP，先关掉再刷新网卡 |
| 底栏 BMC 不变蓝 / 点了没反应 | 先等在线；点的是**窗口最底下**蓝色地址，不是连接页中间的状态卡片 |
| 网页开了但没复制到密码 | 先填对旧板或新板凭据；看终端是否提示「无法通过 IPMI 判断板型」 |
| 日志在哪 / 怎么展开 | 点内容区最底下那条日志或「展开终端」，面板在右侧 |
| DHCP 标签没有 ACK | 网深是否还开着；网卡是否静态；看 DHCP 标签停在 Discover 还是 Offer |
| DHCP 起不来 / 绑 UDP 67 失败 | 关掉网上深度远程启动管理器及其它占 67 的工具，以管理员运行后刷新网卡 |
| 拓扑刷写失败 | 脚本是否在 `ipmitool/`；`.bin` 是否 ≤512 字节；拓扑日志；本机 Python |
| 库里找不到刚放的拓扑 bin | 是否在 **`PCLE/<厂商>/`**；文件名是否等于套餐号；放完后是否点拓扑页 **刷新** |
| 找不到拓扑脚本 | 放入 `ipmitool/`，点刷新 |
| 换板找不到备份 | SN 与 `fru_backup` 中 `{SN}.bin` / `{SN}_时间戳.bin` 一致 |
| 误关程序 | FRU/拓扑写入中勿强制结束 |

## 12. 安全与注意

- 仅在授权设备上使用；勿随意外传 `logs/`、`fru_backup/`
- 换板与拓扑会改非易失数据，操作前确认 SN、机型与拓扑版本
